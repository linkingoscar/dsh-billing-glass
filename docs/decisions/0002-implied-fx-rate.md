# 0002 — 消费统计的隐含汇率与兜底常数

状态：已采纳 · 日期：2026-08-23

## 背景

v0.3.0 及之前，消费统计把 USD 基准合计按**写死的 7.2** 换算成 CNY 展示。
问题：汇率是市场变量，常数会随时间失真；且单币种账本根本不需要换算。

## 决策

1. `ledger.summary()` 每桶新增按 `nativeCurrency` 分组的原生金额合计
   （`native` 字段）——**单币种账本精确展示，换算直接消失**。
2. 混合币种时按 `impliedFxRate()`：现行峰谷政策里 flash 档
   `cny.input / usd.input` 的比值（官方双币价目自declare平价，随政策更新跟随），
   展示保留 ≈ 标注。
3. env `DSH_BILLING_FX_CNY_PER_USD` 可显式覆盖；政策链缺失时回退历史
   常数 7.2。

## 备选方案

- 兜底常数改成设置卡片可配置项——被否：`impliedFxRate` 返回 null 意味着
  政策链本身缺失/过期，此时计价数字整体已不可信，换算率精度无关紧要；
  加配置项是伪需求。（符合上游 dsh「DEFAULT_* 常量不等于可配置性」的
  反向推论：这里连 DEFAULT 都几乎不会走到。）
- 接入在线汇率 API——被否：引入外部网络依赖与密钥面，违背零依赖安装原则。

## 后果

- DeepSeek 单币种用户看到的是精确原生合计（无任何近似符号）。
- 混合币种用户的换算率随官方调价自动更新，无需发版。
