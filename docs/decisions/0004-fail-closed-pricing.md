# 0004 — 未知模型 fail closed，而非估算或按零计费

状态：已采纳 · 自 v0.2.0 起 · 日期：2026-08-23（追溯记录）

## 背景

目录里没有的模型会持续出现：catalog 落后于 Harness、alias 改名、全新模型
（如 v0.1.1-rc.1 新增的 vision-exp）。计费系统必须决定"不知道价格时怎么办"。

## 决策

`priceAt` 对未知模型/未覆盖时段一律返回 **null**；上层把该消息标记为
`priced: false` + `unpricedReason`（model_unknown / pricing_unknown），UI 显示
「未计价 N 条」，账本落 `priced: false`。**绝不静默按 0 元计，也绝不做估算。**

## 备选方案

1. 按 0 元计——被否：统计静默偏低，用户对账时才发现，信任不可逆损伤。
2. 用同系列最近模型价估算并标注——被否：估算值会被聚合进总额，"标注"
   在数字相加后消失；且估算锚点（哪个模型近似？）本身是猜测。
3. wildcard 兜底价——v0.2.0 前的旧做法，已删除：兜底价掩盖目录缺口。

## 后果

- 显示总额可能低于真实账单（少算，不多算）——方向性偏差是刻意选择：
  低估让用户去补目录，高估让用户怀疑插件。
- 每次上游新增模型都需要一次目录/政策同步；漂移监控（0003）负责提醒。
- `unpricedCalls` 成为 UI 一等公民信号，倒逼及时同步。
